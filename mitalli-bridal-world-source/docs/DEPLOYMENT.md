# Deploying to Render

This repo includes `render.yaml`, a Render **Blueprint** — Render reads it automatically
and provisions both the web service and a managed Postgres database in one step.

## One-click / Blueprint deploy (recommended)

1. Push this repo to GitHub (already done if you're reading this from the repo).
2. Go to https://dashboard.render.com and sign in (connect your GitHub account if you
   haven't already — this uses Render's GitHub App / OAuth, **not** a personal access token).
3. Click **New +** → **Blueprint**.
4. Select the `Bridal-makeup-artist-site-` repository. Render will detect `render.yaml`
   automatically and show you the two resources it will create:
   - `mitalli-bridal-world` — the web service (FastAPI app)
   - `mitalli-bridal-db` — a free-tier Postgres database
5. Click **Apply**. Render will build and deploy automatically on every push to `main`.
6. Once deployed, open the service's **Environment** tab and set `ADMIN_PASSWORD` to a
   real password (this is intentionally left out of `render.yaml` so a real password is
   never committed to the repo). `SECRET_KEY` is auto-generated by Render.
7. Visit your live URL (e.g. `https://mitalli-bridal-world.onrender.com`). Log in to
   `/admin/login` with `ADMIN_USERNAME` / the password you just set.

## What render.yaml sets up

- **Runtime:** Python, `pip install -r requirements.txt`, then
  `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
- **Health check:** `/health` — Render uses this to confirm the service is alive.
- **Database:** a free Postgres instance; its connection string is injected into the
  web service automatically as `DATABASE_URL`.
- **Secrets:** `SECRET_KEY` is auto-generated by Render; `ADMIN_PASSWORD` is left for
  you to set manually in the dashboard (`sync: false` in render.yaml means "don't store
  this in the blueprint file").

## First deploy behavior

On startup the app creates all database tables and seeds:
- The service catalog and bridal packages from the project plan (bridal packages are
  seeded but **unpublished** until you confirm pricing/inclusions in the admin panel).
- Site settings, split into verified public info and items flagged "needs owner
  confirmation" (see `app/config.py`).
- One admin user (`ADMIN_USERNAME` / `ADMIN_PASSWORD`).

## Free-tier notes

- Render's free web services spin down after inactivity and take ~30–60s to wake on the
  next request — fine for a low-traffic local business site, but worth knowing.
- Free Postgres databases on Render expire after 90 days unless upgraded to a paid plan.
  Check Render's current free-tier terms before relying on this long-term.

## Redeploying after code changes

Push to `main` — Render auto-deploys. No manual steps needed unless you add new
environment variables (add those in the dashboard's Environment tab).

## Custom domain

Once live, add your domain (e.g. `mitallibridalworld.com`) under the service's
**Settings → Custom Domains** and point your DNS as Render instructs.
